# QA2 편집 확인 목록

샘플 프로젝트를 고치고 저장하는 동작을 확인합니다. 진행 방식과 피드백 형식은 [README](README.md)를 따릅니다.

- 실행: `./scripts/macos/qa.sh --fresh`(편집 QA는 깨끗한 샘플에서 시작합니다)
- 기준 명세: [UX 명세](../design/ux/stellar-ux-spec.md) 흐름 2·5장·6장, [캔버스 편집](../design/ui/canvas_editing.md), [도구·메뉴](../design/ui/tools_menus.md), [사이드바](../design/ui/sidebar.md) 4장, [인스펙터](../design/ui/inspector.md)
- 이 목록은 **제한 모드 그대로** 진행합니다. 캔버스·속성 탭·레이어 편집과 저장은 신뢰와 상관없이 됩니다(사용자 결정 D1). 신뢰(제목 문서 메뉴 또는 File ▸ Trust Project…)는 Git hook·filter, 내장 터미널, MCP·에이전트, 외부 명령 같은 실행 계열에만 필요합니다. 편집 중 신뢰 sheet가 뜨면 결함입니다.
- 먼저 F로 흰 Frame 안에 자식 Frame을 그립니다. 아래에서 ‘새 Frame’은 이 자식을 가리킵니다.
- 저장 전후의 Git 변경은 `git -C <프로젝트 폴더> status --short`로 확인합니다.
- 알려진 한계(지금 빌드): Text 도구는 클릭 생성만 되고 드래그로 고정 폭 Text를 만들지 않습니다(XII.10.33). Image는 드래그로 크기를 정할 수 없고, 도구를 고른 뒤 Frame을 클릭해야 파일 선택이 열립니다(UX.3.3). 핸들을 끄는 동안 도형은 그대로이고 윤곽만 따라가며 놓을 때 한 번 반영됩니다. 회전 핸들은 없습니다.

| QA2-02 | Frame(F)로 기존 Frame 안을 드래그 | 흰 새 Frame을 선택하고 Move 도구로 돌아옵니다. Layers에 행이 하나 생깁니다. |

| QA2-05 | Text(T)로 흰 Frame 안을 클릭하고 글자 입력 → Escape | 기본 글꼴로 Text가 생기고 입력한 글자가 보입니다. 아무것도 입력하지 않고 Escape를 누르면 레이어가 생기지 않습니다. |
| QA2-06 | Insert ▸ Image(⇧⌘K)를 고른 뒤 흰 Frame 안을 클릭 → 파일 선택에서 PNG 고르기 | 클릭한 위치를 왼쪽 위로 삼아 원본 크기의 이미지가 생깁니다. 파일 선택을 취소하면 이전 도구로 돌아갑니다. 32 MiB·16 메가픽셀을 넘는 PNG나 PNG가 아닌 파일은 alert 없이 도구 막대 위 한 줄 안내로 이유가 보입니다. |
| QA2-07 | 생성 도구로 흰 Frame 밖 빈 캔버스를 끌기 | 금지 커서와 도구 막대 위 "Draw inside a Frame." 안내가 2.5초 보이고 아무것도 생기지 않습니다. |
| QA2-08 | Move(V)·Hand(H)·Zoom(Z)을 차례로 고르기 | Move는 선택·이동, Hand는 화면 이동, Zoom은 클릭 확대·Option-클릭 축소입니다(자세한 확인은 QA1 5장). |
| QA2-09 | 위 생성을 모두 한 뒤 ⌘Z를 생성 수만큼, 다시 ⇧⌘Z | 생성 하나가 Undo 하나로 사라지고 다시 실행으로 돌아옵니다. |
