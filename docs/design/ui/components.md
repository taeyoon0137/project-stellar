# 컴포넌트 UI 명세

- 범위: UX.9.1 명세. 실제 연결은 UX.9.2~UX.9.8에서 맡습니다.
- 기준: [UX 명세 흐름 7·7.3·7.4](../ux/stellar-ux-spec.md), [컴포넌트 원본 v1](../../spec/component-source-v1.md), [ADR-0061](../../adr/ADR-0061-text-source-format-and-layout.md).
- 컴포넌트 정의의 원본은 `design/components/` 아래 파일 하나입니다. 정의는 Page나 View의 자식이 아닙니다.

## 에셋 탭

왼쪽 사이드바의 머리 줄 아래에 레이어·에셋·변경 탭을 두되, 연결된 탭만 표시합니다. 에셋 탭의 첫 구획은 Components입니다. 이미지와 토큰 세트는 원본 단위가 정해지기 전에는 표시하지 않습니다. 탭이 하나뿐이면 탭 줄을 그리지 않습니다.

컴포넌트 행에는 비동기로 만든 캐시 썸네일, 이름, 보조 문구로 파일 경로, 파일 단위 Git 상태 배지를 둡니다. 원본 파일이 추가·변경·삭제되면 프로젝트 감시 결과로 목록을 다시 읽습니다. 썸네일 생성과 원본 파일 읽기는 입력 스레드에서 하지 않습니다. 정의가 없는 상태에서는 Components 구획을 빈 상태로 보이고, 만들지 않은 항목을 선택 가능하게 두지 않습니다.

## 만들기와 배치

- Components 구획의 [+]는 목록 안에 이름 편집 행을 만듭니다. Return으로 확정하면 `design/components/`에 원본 파일 하나를 쓰고 바로 그 정의의 편집 범위로 들어갑니다. Escape는 취소하며 파일을 만들지 않습니다. 생성 실패는 행 안에 이유를 보입니다. 연속 alert는 사용하지 않습니다.
- 에셋 행을 캔버스로 끌면 포인터 아래의 부모 Frame을 강조합니다. 흐름 컨테이너라면 삽입 위치 선을 보여 줍니다. 놓으면 인스턴스 하나를 배치하고 Undo 한 번으로 되돌립니다. 좌표를 숫자로 입력하는 배치 대화상자는 없습니다.
- 에셋 행 더블클릭은 정의 편집입니다. 문맥 메뉴에는 이름 변경, Finder에서 보기, 편집기에서 열기, 삭제를 둡니다. 사용처가 있는 정의를 지우려면 확인 sheet를 거칩니다. 경로를 직접 바꾸는 편집은 원본 파일 규칙을 따라야 합니다.

## 정의 편집

정의 편집은 현재 창의 캔버스에서 그 정의의 root Frame만 보이는 범위입니다. 별도 창을 열지 않습니다. 사이드바 머리 줄은 원래 View에서 정의로 온 경로(`Home › Button 정의`)와 [완료]를, 속성 탭 머리는 `편집 대상: Button 정의`를 보여 줍니다. [완료], Escape, 머리 줄의 원래 View로 나오면 이전 View와 카메라를 복원합니다. 정의의 편집도 일반 Command와 같은 Undo 흐름에 기록하고, 저장된 원본이 바뀌면 배치된 인스턴스 표시를 갱신합니다.

정의 편집 중 속성 행의 문맥 메뉴 `인스턴스에서 바꿀 수 있게 공개`가 Component Property 공개 경로입니다. 공개되지 않은 속성을 인스턴스에서 바로 편집하도록 열지 않습니다. 현재 컴포넌트 원본 v3은 빈 공개 인터페이스와 Frame 트리만 쓰므로 Property·Slot 저장이 지원되기 전에는 공개 메뉴를 노출하지 않습니다.

## 인스턴스 속성

인스턴스를 고르면 속성 탭 위에 `<이름> 인스턴스`와 공개 Property·Slot을 배치합니다. override된 행에는 표시와 행별 되돌리기를 둡니다. 비공개 필드는 편집할 수 없는 이유와 `정의 편집` 링크를 보여 줍니다. 자유 편집은 문맥 메뉴의 명시적 Detach 뒤에만 가능합니다. Variant마다 정의 노드를 복제해 격자로 펼치지 않고 View 변수와 희소 override 조합을 사용합니다.

현재 컴포넌트 원본 v3은 Frame 트리와 빈 인터페이스만 저장합니다. 지원하지 않는 Property·Slot·자식 종류를 조용히 버리거나 파일을 다시 쓰지 않습니다. 저장 능력이 없는 항목은 기능 연결 전까지 숨기고, 사용자에게 보이는 항목은 코어 명령이 실제로 처리할 때만 노출합니다.

## Git과 원본

에셋 행의 배지는 해당 `.stellar.yaml` 파일의 Git 상태를 뜻합니다. 변경 탭에서는 컴포넌트 파일을 View와 별도 원본 묶음으로 표시하고, 그 파일만 `커밋에 포함`해 커밋할 수 있습니다. 체크 상태의 원본은 Git index입니다. 파일 이름은 `<이름>-<StableId에서 파생한 접미사>.stellar.yaml`이며, 이름을 바꿀 때 내부 이름과 파일 이름을 함께 맞춥니다. 앱은 다른 컴포넌트 파일을 자동으로 포함하거나 변경하지 않습니다.

## 제외와 연결 조건

- 선택에서 컴포넌트 만들기, 별도 Component Library 창, 숫자 좌표 배치 alert, New Component alert 연쇄를 두지 않습니다.
- 새 정의 쓰기와 편집은 기존 component-source 경로를 사용합니다. 저장 형식·YAML 키를 이 명세에서 바꾸지 않습니다.
- 배치, Detach, Property·Slot 공개, 컴포넌트만 커밋하기는 각각 코어 명령과 Git index 경로가 연결된 뒤에만 화면에 나타납니다.
