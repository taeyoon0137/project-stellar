# ADR-0023: 내장 터미널은 사용자 로그인 셸 환경을 그대로 쓰고 테마만 적용

## Status

Accepted (2026-11-14, 제품 소유자 결정)

## Context

제품 소유자는 2026-11-14에 내장 터미널의 동작 방향을 정했습니다. 내장 터미널은 일반 터미널 앱이나
코드 편집기의 통합 터미널(업계 기준점으로 VS Code)처럼 사용자의 로그인 셸을 사용자의 전체 환경과
설정으로 실행합니다. Stellar가 바꾸는 것은 테마(색, 글꼴, cursor)뿐입니다. 신뢰된 프로젝트에서만
터미널을 시작하는 규칙은 그대로 두고, 앱이 시작하는 에이전트 CLI 하위 프로세스에는 이 방향을 적용하지
않고 허용 목록 환경을 씁니다(결정 9).

현재 구현과 계획 문구는 이 방향과 다릅니다.

- `crates/terminal/src/env.rs`(XVIII.1.1 `[x]`)는 child를 실행할 때 환경을 모두 지우고(`env_clear`)
  상속 허용 목록 9개(`HOME`, `LANG`, `LC_ALL`, `LC_CTYPE`, `LOGNAME`, `PATH`, `TMPDIR`, `TZ`,
  `USER`)와 profile의 명시 지정만 전달합니다. 근거는 ADR-0019 보안 절의 "환경 변수 허용 목록 원칙"입니다.
  예외로 기본 셸 profile은 profile이 `SHELL`을 명시하지 않으면 Stellar가 `SHELL`을 실제로 실행하는 셸
  경로로 설정합니다(`crates/terminal/src/registry.rs`).
- 이 방식에서는 사용자 계정 환경에 있는 변수(예: `SSH_AUTH_SOCK`, 사용자가 launchd에 등록한 변수)가
  셸에 전달되지 않습니다. login 셸이 rc 파일을 읽어 `PATH`·prompt·alias·plugin을 다시 만들기는
  하지만, rc 파일이 기대하는 상속 변수가 없어 일반 터미널 앱과 다르게 동작할 수 있습니다.
- 계획 행 XVIII.1.1은 "environment allowlist"를 세션 기본 타입의 하나로 적고 있어, 대화형 터미널에도
  허용 목록이 요구사항인 것처럼 읽힙니다. 구현 타입 이름은 이미 `EnvironmentPolicy`입니다.
- 셸 선택과 login/non-login(XVIII.2.2 `[x]`)은 이미 계정 데이터베이스의 로그인 셸을 기본으로 쓰고,
  기본 실행 방식은 login 셸입니다. 이 부분은 새 방향과 맞습니다.
- 아키텍처 §32는 "셸, 환경 변수, 시작 명령, 작업 디렉터리 프로필"만 적고 대화형 터미널의 허용 목록을
  요구하지 않습니다.
- ADR-0005 §4.3은 구독 CLI의 두 불변식과 launch profile 내용(실행 설정, decoder profile, 약관·공식 문서
  검토)을 정하지만 CLI 프로세스 환경 변수 목록은 정하지 않습니다. 에이전트 CLI 하위 프로세스의 환경 규칙을
  정한 문서는 아직 없습니다. ADR-0019 보안 절의 "환경 변수 허용 목록 원칙"은 터미널 crate를 대상으로 적은
  원칙입니다.

macOS에서 Finder나 Dock으로 실행한 앱의 프로세스 환경은 사용자 로그인 세션(launchd)의 환경입니다.
rc 파일이 만드는 `PATH` 추가분 등은 이 환경에 없고, login 셸이 시작하면서 직접 만듭니다.

## Decision

1. **적용 범위**: 이 ADR은 사용자가 내장 터미널 패널에서 여는 대화형 터미널 세션(Phase XVIII)에만
   적용합니다. 사용자가 그 세션에서 직접 실행한 CLI(XVIII.5.1, 예: 에이전트 CLI를 일반 명령으로 실행)도
   대화형 세션의 일부입니다. 앱이 내장 에이전트로 시작하는 구독 CLI 세션(ADR-0005, Phase XXIX)은
   대화형 터미널이 아니며 이 ADR을 적용하지 않습니다.
2. **셸**: 기본값은 계정의 기본 로그인 셸을 login 셸로 실행하는 것입니다(XVIII.2.2 기본값 유지).
   사용자가 설정에서 다른 셸이나 non-login을 고르면 그 선택을 따르며, 환경 규칙은 아래와 같습니다.
3. **환경**: 대화형 세션 child는 앱 프로세스 환경을 그대로 물려받습니다. `env_clear`나 상속 허용
   목록을 쓰지 않습니다. 그 위에서 login 셸이 사용자의 rc·profile 파일을 읽어 `PATH`, prompt, alias,
   plugin 등 사용자 설정을 만듭니다. Stellar는 셸 환경을 미리 수집하거나 가공하지 않습니다.
4. **Stellar가 설정하는 변수**: 터미널 식별 변수 `TERM`, `COLORTERM`, `TERM_PROGRAM`,
   `TERM_PROGRAM_VERSION`과 셸 경로 `SHELL`만 설정하며, 상속값이 있으면 이 값으로 덮어씁니다.
   - `TERM` 값은 emulator가 실제로 지원하는 terminfo 항목이어야 하며, 구체 값은 emulator 의존성을
     정하는 XVIII.4.1에서 정해 보고서에 기록합니다.
   - `COLORTERM`은 emulator가 24-bit 색을 지원할 때만 `truecolor`로 설정하고, 지원하지 않으면 상속값을
     제거합니다.
   - `TERM_PROGRAM`은 Stellar 제품 식별자, `TERM_PROGRAM_VERSION`은 앱 버전입니다.
   - `SHELL`은 기본 셸 profile(XVIII.2.2)로 셸을 실행할 때만 실제로 실행하는 셸의 경로로 설정합니다.
     사용자가 계정 로그인 셸과 다른 셸을 고르면 상속된 `SHELL`이 실행 중인 셸과 달라지기 때문이며, 지금
     구현의 동작을 유지합니다. 사용자가 명령(argv)을 직접 지정한 profile에서는 `SHELL`을 바꾸지 않고
     상속값을 그대로 둡니다.
   - 그 밖의 변수(Stellar 내부 상태, MCP 연결 정보, 토큰 등)는 넣지 않습니다. 변수를 더하려면 이 ADR을
     개정합니다.
5. **사용자 명시 지정**: profile에 사용자가 직접 적은 환경 변수 지정(아키텍처 §32 "환경 변수 프로필")은
   유지하며, 상속값과 식별 변수보다 나중에 적용해 사용자 지정이 이깁니다. 이름·값 검증과 상한은
   기존 `EnvironmentPolicy` 규칙을 따릅니다.
6. **셸 설정 무변경**: Stellar는 사용자 셸 설정 파일(rc·profile 등)을 만들거나 고치지 않고, prompt나
   shell integration 스크립트를 주입하지 않으며, 셸 시작 인자에 사용자 설정을 바꾸는 옵션을 더하지
   않습니다. shell integration이 필요해지면 opt-in 기능으로 별도 ADR에서 정합니다.
7. **테마**: Stellar는 터미널 보기에만 Stellar 테마를 적용합니다.
   - 대상은 ANSI 16색 팔레트, 기본 전경·배경, 선택 영역, cursor(색·모양·깜박임), 글꼴(family·크기)입니다.
   - Light·Dark와 대비 높이기 변형을 두고 ShellTheme 이벤트(XII.9.3)에 따라 실행 중에도 바꿉니다. 동작
     줄이기가 켜져 있으면 cursor 깜박임을 끕니다. 색은 앱 셸 규칙대로 asset catalog의 light·dark·고대비
     변형으로 정의합니다(`docs/design/macos-shell-design.md`).
   - 테마 변경은 표시만 바꾸며, 셸 프로세스를 다시 시작하거나 환경 변수를 바꾸지 않습니다.
   - 프로그램이 직접 지정한 256색·24-bit 색과 cursor 모양 요청은 일반 emulator처럼 그 세션 안에서
     표시합니다. 기본 전경·배경 색 질의에는 현재 테마 값으로 응답합니다.
   - 테마와 글꼴 설정은 앱 사용자 설정이며 프로젝트 파일에 넣지 않습니다.
8. **신뢰 게이트 유지**: 터미널은 신뢰된 프로젝트에서만 시작합니다(XVIII.1.4, XVI.7.1). 이 ADR은 이
   게이트를 바꾸지 않습니다.
9. **에이전트 CLI 하위 프로세스**: 앱이 시작하는 구독 CLI 세션은 대화형 터미널의 상속 규칙을 쓰지 않고, 이
   ADR이 정하는 허용 목록 환경으로 실행합니다. ADR-0005 §4.3에는 환경 변수 목록이 없으므로 이 규칙은 이
   ADR의 결정이며, ADR-0019 보안 절의 "환경 변수 허용 목록 원칙"을 구독 CLI에 적용한 것입니다.
   - child 환경은 빈 상태에서 시작하고, launch profile에 적은 환경 변수 이름 목록에 있는 이름만 앱 프로세스
     환경에서 전달합니다. 목록 밖 변수는 전달하지 않습니다.
   - 목록은 launch profile마다 이름만 담고 값은 담지 않습니다. 이름과 그 근거(각 CLI 공식 문서)는 XXIX.2.6이
     정해 profile별 보고서에 기록하고, 목록대로 환경을 만드는 실행기는 XXIX.2.4가 구현합니다.
   - 목록을 쓰는 방식(빈 환경 + 이름 목록)을 바꾸려면 이 ADR을 개정합니다. 목록의 이름을 더하거나 빼는 일은
     launch profile 갱신(XXIX.2.6 절차)으로 합니다.
10. **저장 금지**: 터미널 출력, 프로세스, 환경 값은 프로젝트 파일, Git, recovery snapshot에 넣지 않습니다
    (XVIII.1.1, XVIII.4.6). Stellar는 child 환경 값과 터미널 출력을 진단·로그에 기록하지 않습니다(XVI.8).

## Alternatives

- **현행 유지(`env_clear` + 허용 목록 9개)**: 사용자 계정 환경의 변수가 빠져 일반 터미널 앱과 동작이
  달라지며, 제품 소유자 방향과 맞지 않습니다. 대화형 터미널에는 채택하지 않습니다.
- **허용 목록을 넓히거나 사용자가 편집하게 하기**: 어떤 목록도 사용자 환경 전체와 같아질 수 없고, 사용자가
  누락 변수를 직접 찾아야 합니다. 채택하지 않습니다.
- **앱 시작 시 숨은 login 셸을 실행해 환경을 수집하고 앱 프로세스에 반영**: 터미널 없이 사용자 rc 파일을
  실행하고, 앱 시작 시간을 늘리며, 수집한 환경이 다른 하위 프로세스(Git, 에이전트 CLI)에도 퍼집니다. login 셸이
  어차피 rc 파일을 읽으므로 필요하지 않습니다. 채택하지 않습니다.
- **`SHELL`을 설정하지 않고 상속값을 그대로 둠**: 사용자가 계정 로그인 셸과 다른 셸을 고르면 `SHELL`이
  실행 중인 셸과 달라져, `SHELL`로 하위 셸을 여는 프로그램이 다른 셸을 엽니다. 채택하지 않습니다.
- **Stellar가 `LANG` 등 locale 변수도 설정**: 방향이 정한 범위(식별 변수와 테마)를 넘습니다. locale은
  사용자 계정 환경과 셸 설정이 정합니다. 필요해지면 이 ADR을 개정합니다.
- **shell integration을 기본으로 주입**: 사용자 셸 시작 과정을 바꾸므로 "셸 설정 무변경"과 충돌합니다.
  채택하지 않습니다.

## Consequences

- 내장 터미널에서 사용자가 일반 터미널 앱과 같은 `PATH`, prompt, alias, plugin, agent socket을 씁니다.
- 완료 행 XVIII.1.1이 정의한 "environment allowlist"(구현 타입 `EnvironmentPolicy`,
  `crates/terminal/src/env.rs`)는 대화형 세션에 대해서는 이 ADR로 대체됩니다. XVIII.1.1의 문구와 상태는
  고치지 않고(계획 3. 계획 변경 규칙), 새 행 XVIII.2.5가 대화형 spawn 경로를 바꿉니다. 허용 목록은 앱이
  시작하는 에이전트 CLI 하위 프로세스(결정 9)에만 남습니다.
- 테마 적용은 새 행 XVIII.4.7이 맡습니다.
- 앱 프로세스 환경에 있던 변수는 모두 대화형 셸에 전달됩니다. 개발 중 Xcode 등에서 앱을 실행하면 그
  도구가 넣은 변수도 함께 전달될 수 있습니다. 이는 일반 터미널 앱과 같은 동작입니다.
- 사용자 환경이나 rc 파일이 `TERM`을 다시 바꾸면 emulator와 맞지 않을 수 있습니다. 이는 사용자 설정의
  책임으로 두고, Stellar는 시작 시점 값만 보장합니다.
- ADR-0019 보안 절의 "환경 변수 허용 목록 원칙"은 대화형 터미널에 대해서는 이 ADR로 대체됩니다. 앱이
  시작하는 에이전트 CLI 하위 프로세스에는 결정 9로 같은 원칙을 적용합니다.

## Compatibility

파일 포맷, 공개 FFI, 저장 구조에 영향이 없습니다. 터미널 설정과 테마는 앱 사용자 설정이며 프로젝트
파일에 들어가지 않습니다. `crates/terminal`의 Rust API(`EnvironmentPolicy`)는 XVIII.2.5에서 바뀔 수
있으며, 이 crate의 소비자는 앱 내부뿐입니다.

## Performance

환경을 지우고 다시 만드는 단계가 줄어 spawn 비용이 늘지 않습니다. 셸 시작 시간은 사용자 rc 파일에 따라
달라지며 Stellar 성능 예산에 넣지 않습니다. 테마 변경은 terminal view 재표시만 일으키고 프로세스를 다시
시작하지 않습니다.

## Security

- 대화형 셸은 사용자 계정 권한과 환경으로 실행되며, 이는 사용자가 일반 터미널 앱을 여는 것과 같은 신뢰
  수준입니다. 프로젝트 cwd에서 셸이 자동으로 실행하는 사용자 설정(예: 디렉터리 진입 hook)이 있을 수 있으므로
  신뢰된 프로젝트에서만 시작하는 게이트(XVIII.1.4)를 유지합니다.
- Stellar는 자격 증명을 다루지 않으며(아키텍처 §37.3), Stellar 내부 상태·연결 정보·토큰을 대화형 셸 환경에
  넣지 않습니다(결정 4).
- child 환경 값과 터미널 출력은 진단·로그·recovery snapshot·프로젝트에 남기지 않습니다(결정 10).
- 앱이 시작하는 에이전트 CLI 하위 프로세스는 결정 9의 허용 목록 환경으로 실행해, ADR-0005 §4.3 불변식(사용자
  CLI·도구 설정에 흔적 없음)을 검증할 수 있는 범위로 실행 조건을 좁힙니다.

## Migration

- 저장 데이터 마이그레이션은 없습니다.
- 코드: XVIII.2.5가 대화형 세션 spawn 경로에서 `env_clear`와 상속 허용 목록을 제거하고, 결정 4·5의
  변수 적용 순서를 구현합니다. 허용 목록 환경은 에이전트 CLI 실행기(XXIX.2.4)에 두고, 이름 목록은 launch
  profile(XXIX.2.6)에 둡니다.
- 문서: 계획서 XVIII.2.5·XVIII.4.7 추가, XVIII.4.1(`TERM`·`COLORTERM` 결정 지시)·XXIX.2.4·XXIX.2.6 지시
  보강, 개정 기록 추가를 같은 변경에서 합니다. 완료 행 XVIII.1.1은 고치지 않습니다. 아키텍처 §32는
  대화형 터미널의 허용 목록을 요구하지 않으므로 고치지 않습니다.
