# ADR-0003: 자식 순서 키(OrderKey) 알고리즘

## Status

Accepted

## Context

자식 순서는 배열 인덱스를 정체성으로 쓰지 않고 결정론적 `OrderKey`로 결정합니다(기술
아키텍처 12.7). III.5.1에서 요구사항(R1~R5)과 실패 fixture를 작성했고, III.5.2는 알고리즘을
확정·구현합니다. 핵심 제약은 다음과 같습니다.

- 앞·뒤·사이 삽입을 모두 지원.
- 서로 다른 브랜치가 중앙 조정 없이 동시에 삽입 가능(분산 협업·Merge).
- **키 생성에 난수를 사용하지 않음**(결정성·재현성, 양 플랫폼 동일).
- 키는 비교 가능한 byte sequence이며 사전식 순서가 곧 시각 순서.
- 반복 삽입으로 키가 길어지면 부모 단위 재균형으로 길이를 회복.

## Decision

**결정론적 fractional indexing(base-256 소수 byte string)**을 채택합니다.

- 키는 `Vec<u8>`이며 0~1 사이 base-256 소수로 해석합니다(각 byte가 소수 자릿수).
  사전식 byte 비교 = 소수 값 비교입니다.
- 정규형: 키는 **비어 있지 않고 `0x00`으로 끝나지 않습니다**(후행 0은 같은 값의 다른 표현
  이므로 금지). 이로써 같은 값 = 같은 byte열이 되어 비교·동등이 일관됩니다.
- `between(left, right)`는 좌/우 이웃 소수 사이의 키를 **결정론적 중간값**으로 생성합니다.
  `left=None`은 하한(0.0), `right=None`은 상한(1.0)입니다. 자릿수를 앞에서부터 비교해 두
  자릿수 사이에 간격이 있으면 그 중간 자릿수를 채택하고, 간격이 없으면 좌측 자릿수를 따라
  내려갑니다. 항상 0이 아닌 자릿수로 끝나 정규형을 유지합니다.
- **동시 브랜치 충돌**: 두 브랜치가 같은 이웃 사이에 삽입하면 동일 키를 만들 수 있습니다.
  이때 최종 순서는 자식의 `StableId`로 tie-break 합니다(키 동일 → `StableId` 오름차순).
  난수 jitter 대신 이미 존재하는 안정 식별자를 사용해 결정성을 유지합니다.
- **길이 상한·재균형**: 키 길이가 `REBALANCE_THRESHOLD`(16 byte)를 넘으면
  `needs_rebalance`가 참이 됩니다. 부모 단위 재균형(III.5.3)이 시각 순서를 보존하며 키를
  균등 재배치해 길이를 회복합니다.

## Alternatives

- **LSEQ / 난수 경계 전략**: 자리별 할당 경계를 난수로 정해 interleaving을 줄이지만 **난수
  사용** 제약에 위배 — 미선택.
- **Figma류 fractional index + 난수 suffix**: 동시 충돌 회피에 난수를 사용 — 제약 위배.
  본 결정은 난수 suffix를 `StableId` tie-break으로 대체 — 선택.
- **정수 인덱스 재배치**: 모든 삽입이 뒤 형제 인덱스를 갱신해 Merge 충돌·쓰기 증폭 — 미선택.
- **부동소수 위치값**: 정밀도 한계로 사이 삽입이 빠르게 고갈 — 미선택.

## Consequences

- 모든 환경에서 같은 (좌, 우) 입력은 같은 키를 만들어 결정성·재현성을 보장합니다.
- 동시 브랜치 삽입이 중앙 조정 없이 가능하고, 동일 키 충돌은 `StableId`로 안정적으로 풀립니다.
- 반복 삽입으로 키가 자라도 재균형으로 길이를 회복합니다(III.5.3).
- 키 정렬은 byte 사전식 비교라 저장·비교·Merge가 단순합니다.

## Compatibility

- `OrderKey`는 저장 포맷의 일부가 됩니다. byte sequence 표현과 정규형(비어 있지 않음, 후행
  0 금지)은 계약입니다. 비교는 사전식으로 고정됩니다.

## Performance

- `between`은 자릿수 길이에 선형(일반적으로 1~수 byte)인 O(L) 연산이며 할당 1회입니다.
- 100만 회 임의 삽입 property test에서 중복·순서 역전이 없어야 합니다(III.5.2 완료 기준).

## Security

- 키 생성은 외부 입력 없이 좌/우 이웃만 사용합니다. `from_bytes`는 비정규(빈 키, 후행 0)
  입력을 거부합니다.

## Migration

- 신규 결정이라 마이그레이션 대상 데이터가 없습니다. 알고리즘 변경 시 본 ADR을 supersede
  하고 기존 키의 재해석·재생성 절차를 별도 WBS로 정의합니다.
