# ADR-0073: macOS 셸 배치와 상태 표시

## Status

Accepted (2026-11-15). 제품 책임자가 UX 명세(`docs/design/ux/stellar-ux-spec.md`) 16장 결정 항목의 판단을 위임했고, 그중 셸 배치·상태 표시 항목(U1·U2·U4·U5·U12·U13·U15·U16·U17)과, 새 프로젝트 첫 화면의 상태를 정하는 신뢰 등록 항목(U8)을 명세의 권장안으로 확정합니다.

- macOS 셸 디자인 가이드(`docs/design/macos-shell-design.md`)의 열린 결정 O4·O8을 닫습니다. O2(캔버스 확장)는 방향만 정하고, 측정·적용 행 UX.3.10에서 닫습니다(결정 3).
- 이 ADR은 구현 계획과 아키텍처 본문을 바꾸지 않습니다. 계획 XIV.13.5(Git 패널 위치)와 XVI.11.8(초기 빌드 노출 금지)의 개정, 결정 10이 예외를 두는 아키텍처 §24.3("처음 여는 프로젝트는 제한 모드") 문구의 개정은 UX WBS 초안의 UX.0.3이 합니다. 결정 10은 그 개정이 들어간 뒤에 적용합니다.
- 화면 흐름과 사건별 반응의 세부는 UX 명세 3장이 정본이고, 이 ADR은 그 가운데 영역 배치와 상태 표시의 결정, 그리고 첫 화면의 신뢰 상태를 정하는 새 프로젝트 신뢰 등록(결정 10)을 기록합니다.

## Context

- 프로젝트 창의 골격은 이미 정해져 있습니다: 사이드바·캔버스·인스펙터 3열, 캔버스 하단 가운데 도구 막대, 구분선 없는 블러 상단 바(2026-11-14 사용자 결정).
- 되돌림 기준선 `02397601`의 셸에는 그 위에 다음이 남아 있습니다.
  - 캔버스 아래 보조 패널에 Git 탭과, 버튼 없이 안내만 있는 Agent 탭(`DisconnectedAgentPanelSource`)이 있습니다. 셸 가이드 2.4는 이 자리를 초기 릴리스에 노출하지 않는다고 적었습니다.
  - 툴바의 뒤로·앞으로·프로젝트 검색은 코어 경로가 없어 늘 비활성입니다. 더 보기 메뉴에는 신뢰 전 Finder·닫기만 있어 신뢰를 부여할 자리가 없습니다.
  - 부제목은 신뢰 전 "Restricted Mode"만 보이고 브랜치·변경 수는 보이지 않습니다.
  - 메뉴 막대에 기능이 없어 늘 비활성인 항목이 많습니다.
  - 빈 캔버스(root Frame 밖) 드래그처럼 반응 없는 조작이 있고, 그 이유를 알릴 자리가 없습니다.
  - 변경·충돌·출처 표시가 영역마다 다르거나 없습니다.
- 사용자 지시(2026-11-15): 보이는 것은 모두 동작해야 하고, 정의하지 않은 도구·UI를 더하지 않습니다. 제품의 핵심은 Git 협업, 입력 성능, CSS 속성과 실제 코드의 대응, 앱·CLI·MCP가 같은 파일을 편집하는 흐름입니다.
- 셸은 표시와 입력 전달만 맡고, 편집 의미와 semantic status는 코어가, Stage 상태의 원본은 Git index가 가집니다(아키텍처 §8.1, §26.3).

## Decision

1. **캔버스 아래 보조 패널을 두지 않습니다(U1).** 보조 패널과 그 토글을 지웁니다. Git은 사이드바 변경 탭, 에이전트는 오른쪽 에이전트 탭이 맡습니다. 내장 터미널(ADR-0023)의 자리는 이 ADR의 범위 밖입니다(U19).

2. **탭 구성(U1·U12·U13).**
   - 왼쪽 사이드바: 머리 줄 한 줄(평소 `Page 1 › Home ▾` 팝업, 컴포넌트 정의 편집 중 `Home › Button 정의 [완료]`)과 레이어·에셋·변경 탭. 변경 탭이 Git 패널입니다(O4 닫음).
   - 오른쪽 영역: 속성(기본)·코드·에이전트 탭. 코드 탭은 선택한 것의 CSS·HTML·원본 텍스트를 읽고 복사만 하며 편집하지 않습니다. 에이전트 탭은 attached `stellar-mcp`(XIX.9.4)나 내장 세션 실행 경로(XXIX.2·XXIX.3)가 연결된 뒤에만 생깁니다.
   - 탭은 기능이 연결된 뒤에만 생기고, 한 영역에 탭이 하나뿐이면 탭 줄을 그리지 않습니다.
   - 앱은 패널을 자동으로 열거나 숨기거나 다른 탭으로 바꾸지 않습니다. 맥락에 따라 바뀌는 것은 패널 안 섹션, 캔버스 핸들·overlay, 배지입니다. 사건별 반응은 UX 명세 3.4절 표를 따릅니다.
   - 사이드바와 오른쪽 영역의 기본 너비는 320pt입니다.
   - 이유: 변경을 검토하는 동안 변경 목록(왼쪽), 캔버스 변경 윤곽(가운데), 속성의 HEAD 값(오른쪽)을 동시에 보게 하기 위해서입니다.

3. **캔버스를 사이드바·오른쪽 영역 아래로 확장하는 방향으로 정합니다(U2, 측정 후 확정).** drawable 크기·hit test·렌더 비용이 바뀌므로, UX.3.10에서 Release로 측정해 성능 계약(아키텍처 §6) 안일 때만 켜고 그때 셸 가이드 O2를 닫습니다. 계약 밖이면 켜지 않고 측정 결과를 기록합니다. 그 전까지는 지금처럼 겹치지 않게 둡니다.

4. **상단 바(U4).**
   - 앞쪽: 사이드바 토글, 제목(프로젝트 이름, 앱 이름 없음), 부제목. 제목을 누르면 문서 메뉴가 열립니다: Finder에서 보기, 프로젝트 신뢰…(제한 모드일 때) 또는 신뢰 철회(신뢰했을 때), 프로젝트 닫기. 신뢰 부여 항목은 늘 있습니다.
   - 뒤쪽: 에이전트 상태 항목(세션 진행·승인 대기 수·외부 MCP 연결 수, 세션·연결·승인 대기가 있을 때만 보이고 누르면 에이전트 탭을 엶), 줌 메뉴, 인스펙터 토글.
   - 뒤로·앞으로, 프로젝트 검색, 더 보기 메뉴는 지웁니다. 기능이 생기면 다시 설계합니다. Git 동작 버튼은 툴바에 두지 않습니다.
   - 하단 도구 막대에는 도구 10종만 두고 캔버스 영역 하단 가운데에 둡니다. 텍스트 편집 중에도 유지합니다.

5. **부제목은 Git 상태 문법을 따릅니다(U4).** 부제목은 누를 수 없는 지속 상태 표시입니다. 동작은 변경 탭, Git 메뉴, 제목 문서 메뉴에 둡니다.

   | 상태 | 문구 예 |
   |---|---|
   | 깨끗함 | `main · 변경 없음` |
   | 변경 있음 | `main · 변경 4` |
   | 보낼 커밋 있음 | `main · 변경 4 · 보낼 커밋 1` |
   | 병합 중 | `main · 병합 중 · 충돌 3` |
   | 분리된 HEAD | `분리된 HEAD · a1b2c3d` |
   | 제한 모드 | `제한 모드 · Git 꺼짐` |
   | 저장 실패 | 앞에 경고 글리프와 `저장 안 됨` |
   | 에이전트 작업 중 | 끝에 `· 에이전트 작업 중` |

   - 위 문구는 의미만 정합니다. 최종 문구와 언어는 `String(localized:)` 현지화 경로를 따릅니다.
   - 평소 자동 저장은 아무것도 표시하지 않습니다. "Restricted Mode" 상시 표시는 없앱니다.

6. **도구 막대 위 한 줄 안내(U5).** 하단 도구 막대 위에 한 줄 안내 자리를 둡니다. 내 조작의 즉시 결과(그릴 수 없는 곳, 잠긴 범위, 받지 않는 파일 형식)를 사건 뒤 2.5초 동안 또는 다음 입력까지 보여 주고, 같은 문구를 VoiceOver announcement로 알립니다(보통 우선순위, 오류는 높음). 셸 표시이며 캔버스 렌더 결과와 내보내기에 들어가지 않습니다.

7. **알림 수단을 결과의 성격으로 고릅니다.**

   | 수단 | 쓰는 경우 |
   |---|---|
   | sheet | 같은 프로젝트를 연 다른 Stellar 창이 먼저 저장함(두 선택지), 저장 실패·stale 상태에서 창 닫기(D6), 되돌릴 수 없는 작업 확인, 신뢰 확인·에이전트 첫 사용 고지·에이전트의 commit·push 개별 확인·MCP 첫 연결 승인 |
   | 도구 막대 위 한 줄 안내 | 내 조작의 즉시 결과 |
   | 탭 머리 줄 | 그 탭 작업의 결과·실패·진행(예: 커밋함 `a1b2c3d`, Push 실패 이유, 외부 변경 반영 N개) |
   | 부제목 | 지속 상태(결정 5) |
   | 캔버스 overlay | 변경 윤곽, 잠금 윤곽, 짧은 강조 |

   - 쓰지 않는 것: NSAlert 연쇄, 확인 버튼 하나뿐인 막다른 alert, 캔버스 위 토스트.
   - 만들기·다듬기·배치 경로에는 모달 대화상자를 두지 않습니다.

8. **상태 표시 공용 사전(U15).** 캔버스, 레이어 행, 속성 행, 변경 행이 같은 모양을 씁니다.

   | 상태 | 모양 | 표시하는 곳 | 원본 | 단계 |
   |---|---|---|---|---|
   | 추가됨 | 더하기 배지, 캔버스는 실선 윤곽 | 캔버스, 레이어 행, 변경 행 | semantic status `AddObject` | 초기 |
   | 수정됨 | 점 배지, 캔버스는 점선 윤곽 | 캔버스, 레이어, 속성 행, 변경 행 | `SetProperty` 등 | 초기 |
   | 충돌 | 경고 삼각형 | 캔버스, 레이어, 속성, 변경 행 | unmerged conflict | 초기 |
   | 에이전트 출처 | 출처 글리프 + 세션 이름 | 레이어, 속성, 변경 행, 켜고 끄는 캔버스 윤곽 | 세션 메모리(§31.5) | 초기 |
   | 에이전트 잠금 | 점선 범위 윤곽 + 잠금 글리프 | 캔버스, 속성 머리 | lease(§31.4) | 초기 |
   | 외부 출처 | 다른 출처 글리프(이 세션 동안만) | 레이어, 속성, 변경 행 | 세션 메모리 | 초기 |
   | 커밋에 일부 포함 | 반만 찬 배지 | 변경 행, 레이어 | Index Snapshot | 의미 Stage 뒤 |
   | 이동·재정렬·삭제 | 이전 위치 점선 고스트 | 캔버스(변경 탭이 열려 있을 때만), 변경 행 | `MoveObject`·`ReorderObject`·`RemoveObject` | 후순위(U23) |

   - 색만으로 구분하지 않고 글리프 모양과 접근성 레이블로도 구분합니다. 색은 ShellTheme가 정하고(셸 가이드 O9), 글리프는 SF Symbols에서 고르며 이름은 구현 행에서 정합니다.
   - 출처(에이전트, 외부)는 세션 메모리에만 있는 표시입니다. Git 상태의 원본은 Git index입니다.
   - 캔버스 변경 윤곽은 변경 탭이 열려 있을 때 자동으로 켜지고, View 메뉴 "변경 윤곽 늘 보기"로 유지할 수 있습니다. 선택 윤곽과 겹치면 선택이 위입니다.
   - 캔버스 overlay(선택·핸들, hover, 스냅 가이드, 충돌 배지, 변경 윤곽, 잠금 윤곽, 출처 윤곽)는 모두 임시 표시이고 렌더 결과·내보내기에 들어가지 않습니다.

9. **메뉴 막대(U16·U17, O8 닫음).**
   - 순서: 앱, File, Edit, View, Insert, Object, Git, Window, Help.
   - 기능이 연결된 명령만 둡니다. 잠깐 쓸 수 없는 상태(선택 없음 등)만 비활성으로 두고 이유는 한 가지로 도움말에 적습니다. 기능 행이 들어오기 전의 항목은 그 행이 메뉴에 함께 추가합니다.
   - Git 메뉴: 변경 보기, 커밋(변경 탭 포커스에서 ⌘↩), Push, 다음 충돌로 이동, 상태 새로 고침, 프로젝트 신뢰…. 툴바에 두지 않는 Git 동작은 메뉴에 모두 있습니다.
   - View 메뉴: 사이드바·인스펙터 토글, 탭 전환 항목, 줌, "변경 윤곽 늘 보기"·"에이전트 출처 윤곽 보기" 토글, 스냅 토글(XII.10.17). 각 기능이 연결될 때 항목이 생깁니다.
   - Help: 도움말 콘텐츠가 생기기 전에는 앱 도움말 항목을 두지 않습니다.
   - 탭 전환 단축키: 오른쪽 영역은 macOS 인스펙터 관례인 ⌥⌘1–3입니다. 왼쪽 탭 단축키는 왼쪽에 탭이 둘 이상 연결되는 행(UX.5.2)에서 정합니다(후보 ⌘1–3).

10. **Stellar가 새로 만든 프로젝트는 만들 때 신뢰 목록에 등록합니다(U8).** 아키텍처 §24.3 "처음 여는 프로젝트는 제한 모드입니다"의 예외입니다.
    - 대상: Stellar가 §25.1 새 프로젝트 절차(새 디렉터리 생성, `git init -b main`, 기본 파일 생성, 최초 커밋)를 끝까지 성공한 폴더 하나입니다. 생성이 실패하거나 취소되면 등록하지 않습니다.
    - 제외: Clone한 폴더, 이미 있던 폴더 열기, 최근 항목 열기는 지금처럼 제한 모드로 엽니다.
    - 근거: 폴더와 `.git`을 Stellar가 방금 만들었으므로, 저장소 안에 다른 사람이 넣은 hook·filter·외부 diff·merge driver 설정이 없습니다. 새 프로젝트를 만든 직후 신뢰 확인 sheet를 한 번 더 띄우면 흐름 1의 완료 기준(만들기를 누른 뒤 첫 드래그까지 대화상자 0개, UX 명세 4장)과 맞지 않습니다.
    - 방법: 생성을 마친 코어가 그 폴더의 실제 경로와 프로젝트 ID로 기존 신뢰 저장소(사용자 데이터 위치의 `FileTrustStore`)에 등록합니다. 사용자가 신뢰를 부여할 때와 같은 저장소·같은 기록이며, Git 전역 설정은 바꾸지 않습니다(§24.3 마지막 문장 유지).
    - 적용 시점: 아키텍처 §24.3 문구 개정(UX.0.3) 뒤 UX.5.9에서 구현합니다. 그 전까지는 §24.3대로 Stellar가 만든 프로젝트도 처음 열면 제한 모드입니다.

## Alternatives

| 대안 | 판단 |
|---|---|
| Git을 오른쪽 탭으로(U1 대안) | 변경 목록과 속성의 HEAD 값을 동시에 볼 수 없습니다. 미선택 |
| 보조 패널을 유지하고 Git·에이전트·터미널을 그 탭에 둠 | 셸 가이드 2.4의 초기 릴리스 미노출과 맞지 않고, 기능이 없는 탭이 남습니다. 미선택 |
| 에이전트를 인스펙터 옆 별도 trailing 열로(U13 대안) | 창의 열이 넷이 되어 캔버스 폭이 줄고 분할 구조가 늘어납니다. 미선택 |
| 캔버스를 겹치지 않게 계속 유지(U2 대안) | 패널을 여닫을 때 캔버스 내용이 밀립니다. 측정으로 확장 비용이 확인되기 전까지만 유지합니다 |
| 부제목을 비움(U4 대안) | 브랜치·변경 수를 보려면 탭을 열어야 합니다. 미선택 |
| 한 줄 안내 없이 커서 모양만(U5 대안) | 거부 이유를 알 수 없고 VoiceOver 사용자에게 전달되지 않습니다. 미선택 |
| 캔버스 윤곽 없이 레이어·속성 표시만(U15 대안) | 바뀐 것을 캔버스에서 읽을 수 없습니다. 미선택 |
| Git 명령을 File 메뉴 하위에 둠(U16 대안) | 툴바에 두지 않는 Git 동작을 한 곳에서 찾기 어렵습니다. 미선택 |
| 왼쪽 탭에 ⌘1–3을 바로 배정(U17 대안) | 지금 왼쪽에 탭이 하나뿐이라 배정할 대상이 없습니다. 탭이 늘 때 정합니다 |
| 영구 비활성 메뉴·툴바 항목을 진열해 둠 | "보이는 것은 모두 동작한다"는 사용자 지시와 맞지 않습니다. 미선택 |
| 새 프로젝트도 늘 제한 모드로 시작(U8 대안) | 방금 만든 폴더에 신뢰 확인을 한 번 더 받아야 하고, 첫 화면 부제목이 `제한 모드 · Git 꺼짐`이 됩니다. 미선택 |

## Consequences

- 장점
  - 눌러서 반응 없는 UI가 없어지고, 신뢰를 부여할 자리가 늘 있습니다.
  - 사람·에이전트·외부 파일·병합의 변경이 캔버스, 레이어 행, 속성 행, 변경 목록 네 곳에 같은 모양으로 보입니다.
  - 브랜치와 변경 수를 부제목에서 늘 볼 수 있습니다.
  - 새 프로젝트는 첫 화면부터 Git 상태(`main · 변경 없음`)와 Git 동작을 씁니다(결정 10 적용 뒤).
- 단점과 남는 일
  - 결정 10은 아키텍처 §24.3과 어긋나므로 §24.3 문구를 먼저 개정해야 합니다(UX.0.3).
  - 기준선의 보조 패널·툴바 항목·영구 비활성 메뉴를 지우고(UX.1.1·UX.1.2·UX.1.4), Git 패널을 사이드바 탭으로 옮겨야 합니다(UX.5.2).
  - 탭 줄 규칙, 한 줄 안내, 상태 사전, 캔버스 overlay를 새로 구현해야 합니다.
  - 코드·에이전트 탭은 계획 XVI.11.8과 충돌하므로 탭을 넣기 전에 계획 개정(UX.0.3)이 필요합니다.
  - 제한 모드에서 Git을 실행하지 않고 `.git/HEAD`만 읽어 브랜치 이름을 보여 줄 수 있는지는 확인하지 못했습니다. 확인 전에는 제한 모드 부제목을 `제한 모드 · Git 꺼짐`으로 둡니다.
  - 내장 터미널의 자리는 정하지 않았습니다(U19).

## Compatibility

- 프로젝트 파일 포맷, 공개 API, FFI, 스키마를 바꾸지 않습니다. 셸 표시와 메뉴 구성만 바뀝니다.
- 창 상태 기록: 보조 패널 split autosave(`StellarMainWindow.CenterSplit`)는 더 쓰지 않습니다. 남은 기록은 무시하며, 창 프레임과 3열 pane 폭·접힘 복원은 깨지지 않아야 합니다(UX.1.1 검증 기준).
- 메뉴에서 빠지는 명령의 `ShellCommand`와 단축키는 기능 행이 들어올 때까지 다른 명령에 쓰지 않고 예약합니다(`docs/design/ui/tools_menus.md` 6.1).

## Performance

- 부제목, 배지, 캔버스 윤곽은 키 입력마다가 아니라 자동 저장 flush 뒤 worker에서 계산한 semantic status 결과로만 갱신합니다. Git 명령은 메인 스레드에서 실행하지 않습니다.
- 입력에서 Present 예약까지 10ms 계약과 UI 스레드 단일 점유 2ms 상한(아키텍처 §6)은 그대로입니다. 한 줄 안내와 overlay는 이 경로를 막지 않아야 합니다.
- 캔버스 확장(결정 3)과 변경 윤곽 overlay의 비용은 아직 측정하지 않았습니다. 확장은 UX.3.10(캔버스 확장 측정·적용), 변경 윤곽은 UX.6.4(변경 윤곽 overlay)에서 Release로 측정해 기록합니다.

## Security

- 제한 모드는 Git hook·filter, 내장 터미널, MCP·에이전트, 외부 명령 같은 실행 계열만 막습니다(D1, 아키텍처 §24.3). 캔버스·속성·레이어 편집과 저장은 신뢰와 상관없이 됩니다. 신뢰 부여는 제목 문서 메뉴, 변경 탭(제한 모드), Git 메뉴에 있고, 철회는 제목 문서 메뉴에 있습니다.
- 결정 10(U8)의 보안 영향
  - 사용자가 직접 결정하지 않아도 신뢰가 생기는 유일한 경로입니다. 대상은 Stellar가 §25.1 절차로 끝까지 만든 폴더뿐이고, Clone·열기에는 쓰지 않습니다. 이 경계는 UX.5.9의 코어 단위 테스트로 고정합니다(새 프로젝트 = 신뢰, Clone·열기 = 제한 모드, 생성 실패 = 등록 없음).
  - `git init`은 사용자의 Git 설정(`init.templateDir`, 전역 `core.hooksPath`)을 따르므로, 사용자가 직접 설정한 hook은 신뢰 뒤 실행될 수 있습니다. 이는 사용자가 터미널에서 같은 저장소를 쓸 때와 같은 범위이고, 다른 사람이 저장소 안에 넣은 hook은 아닙니다.
  - 등록한 뒤 앱 밖에서 폴더에 hook 등이 더해지는 경우는 사용자가 신뢰한 다른 프로젝트와 같게 다룹니다. 철회는 제목 문서 메뉴에서 합니다.
- 에이전트 UI와 승인 화면은 캔버스 위에 그리지 않습니다(ADR-0005 결정 4.5). 캔버스에는 잠금 범위·변경 윤곽 같은 표시만 둡니다.
- 부제목과 한 줄 안내의 프로젝트 유래 문자열은 화면 표시에만 쓰고 OS 알림 본문·진단 기록에 넣지 않습니다(아키텍처 §39).

## Migration

- 코드 이행은 UX WBS 초안(`docs/design/ux/ux-wbs-rows.md`)의 행으로 합니다: UX.1.1(보조 패널 삭제), UX.1.2(영구 비활성 UI 삭제), UX.1.4(제목 문서 메뉴), UX.2.8(한 줄 안내), UX.3.10(캔버스 확장 측정·적용), UX.5.2(변경 탭), UX.5.3(부제목), UX.5.8(Git 메뉴), UX.5.9(새 프로젝트 신뢰 등록, 결정 10), UX.6.2·UX.6.4(배지·윤곽), UX.7.1(오른쪽 탭 자리와 탭 줄 규칙), UX.10.3(에이전트 탭·상태 항목).
- 문서는 UX.0.2에서 셸 가이드와 영역 명세(`docs/design/ui/`)를 이 결정에 맞췄습니다.
- 데이터 이행은 없습니다.
