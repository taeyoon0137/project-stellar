# macOS Git 패널의 저장 노드 이름 Stage와 Unstage

## 사용자 경로

프로젝트를 열고 **보기 → 패널 보기 → Git**을 선택합니다. 처음 연 폴더에서는 **Trust Project**를 누르고 표시된 폴더를 확인합니다. 취소하면 사용자 신뢰 파일을 만들지 않습니다. **Revoke Project Trust**는 창의 추가 동작 메뉴에 있습니다. 신뢰 상태는 기존 사용자별 저장소가 프로젝트 ID와 실제 폴더를 모두 확인합니다.

시스템 Git에 이미 커밋된 저장 프로젝트에서 노드 이름을 편집하고 저장한 다음 Git 패널을 새로고침합니다. 문서와 노드를 펼쳐 **Node name** 행의 체크박스를 누르면 그 이름 한 건을 실제 index에 적용합니다. 이미 Stage한 이름의 체크를 해제하면 HEAD의 이름을 index에 되돌리고 작업 파일의 편집은 유지합니다. 패널은 HEAD·index·저장된 작업 트리의 이름을 비교합니다. 저장한 뒤 클릭하기 전 이름이 또 바뀌면 현재 목록을 새로고침해야 합니다.

## 구현 범위

- `stellar_git_names_request`는 창 handle을 받아 백그라운드에서 기존 candidate 준비·검증·적용을 호출합니다. 표시 세대와 코어에 보관한 선택 diff를 함께 확인합니다. 결과는 기존 runtime 이벤트 펌프로 전달하고 실제 Git index를 다시 읽습니다.
- 한 창에 실행 중인 Git 작업은 한 건이며 runtime 전체에서 두 건까지 접수합니다. 창 닫기, 신뢰 철회와 작업 취소는 해당 요청의 취소 토큰을 사용합니다. 게시 전 취소하면 index를 보존합니다. 이미 게시된 뒤 재조회가 실패하면 다시 조회할 수 있도록 결과에 게시 사실을 포함합니다.
- 현재 사용자 경로는 저장된 기존 노드의 이름 한 건의 Stage와 Unstage입니다. 같은 청크에 있는 다른 속성은 작업 트리에 남습니다. 다른 의미 변경이 있는 프로젝트에는 이름만 표시한다는 안내를 보냅니다. 이름 변경 64건 또는 행 이름 4,096 UTF-8바이트의 표시 한도를 넘으면 목록을 거부합니다.
- 조회는 worker가 저장 세대를 materialize해 비교합니다. 아직 대형 프로젝트에 대한 지연 시간이나 100만 행의 실제 FFI 페이지 성능을 측정하지 않았습니다. Commit·Push와 다른 종류의 변경을 패널에서 적용하는 작업은 후속 범위입니다. XIV.13 전체 완료 상태를 변경하지 않았습니다.

## 재현과 인계

`./scripts/macos/smoke.sh`는 임시 HOME과 실제 Git 저장소에서 CLI로 정상 저장한 세대를 사용합니다. `--project-trust-check`가 AppKit 신뢰 sheet 취소·승인·철회·재열기를 확인합니다. `scripts/macos/git-stage-check.py`는 `--git-stage-check`로 패널 체크박스를 누른 다음 시스템 Git의 `checkout-index` 결과를 별도로 엽니다. Stage 뒤에는 이름이 index와 작업 트리에 함께 보입니다. 재열린 창에서 체크를 해제하면 index 이름은 HEAD와 같고, 작업 파일에는 이름과 잠금 변경이 모두 남습니다. 두 시점의 index를 독립적으로 재열어 확인합니다. 같은 흐름에서 미신뢰·취소·오래된 선택의 index 불변과 조회 중 닫힌 창의 늦은 결과 폐기를 검사합니다.
